## Narrow optional measurement UI design: no real measurements executed
- Primary path: manually enter length × width × height **cm** and explicitly confirm.
- Optional **calibrated reference photo**: only display candidate cm when known-size reference and scale validation are present; an uncalibrated image cannot give absolute real-world dimensions. For packaged/irregular items request the outer bounding measurements.
- Alternative **device AR/depth**: only on supported hardware with validated measurement; compare actual phone coverage and ground-truth error first. **Specialist SDK** is another unselected option requiring commercial, privacy, retention and Australian eligibility review.
- Permission denied, offline, failed upload, unsupported sensor, missing reference or unusable estimate => **manual fallback**. Candidate numbers are **approximate / not independently verified** and require customer review/correction and confirmation before any future authorised API save. No guessed weight, chargeable/billing dimension, vehicle-fit certificate or fabricated confidence percentage.
- Proposed provenance: manual | reference-photo | device-depth, plus customer confirmation and calibrated-method metadata. Design only; no DB migration, storage, third-party processing, uploads or devices.

## Framework decision NOT MADE
React Native + Expo + TypeScript is a **candidate**, not an owner-selected framework. Flutter is a second shared-codebase choice; native Swift/Kotlin maximizes device-specific control with duplicated app maintenance. Existing Next.js/Clerk/Prisma website remains backend authority; native authentication and tenancy need independent review. Australia first (AUD, cm, Australian addresses); international expansion later.
